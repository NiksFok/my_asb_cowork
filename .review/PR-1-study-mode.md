## Что делает

Третья изолированная tmux-сессия Claude («d-study») — репетитор на более дешёвой
модели. Кнопка «🎓 Учёба» и команда `/study`. При первом запуске (нет
`vault/study/profile.md`) проводит интервью из 5 вопросов и сам создаёт
`profile.md` + `plan.md`. Прогресс пишется в `vault/study/`, файлы получают тип
`learning` в `.memory-config.json`. Утренний брифинг получает одну строку
«🎓 Сегодня по плану: …». Бонусом — глобальный роутер для кнопок «🛑 Завершить…».

Архитектурно повторяет уже существующий паттерн `get_cron_session` — ложится в
кодовую базу органично.

## Проверка кода (построчно сверено с текущим main)

Всё, что PR вызывает, в репозитории существует и сигнатуры совпадают:
`ClaudeSession(... mcp_config, system_prompt_file, model, env_prefix)`,
`_persisted_name`, `do._extract_prompt`, `settings.runtime_dir`. Новых
зависимостей, сетевых вызовов и секретов не добавляет. Вредоносного в
persona-файле и скилле нет — это обычная методичка репетитора.

### Что надо поправить до merge

1. **`STUDY_MODEL=claude-sonnet-5` — скорее всего невалидный ID модели.**
   `.env.example` прямо над этой строкой перечисляет допустимые варианты:
   `claude-opus-4-8 | claude-sonnet-4-6 | claude-haiku-4-5-20251001`.
   В `config.py` дефолт тоже `claude-sonnet-5`. Если ID не распознаётся, учебная
   сессия падает на холодном старте. Фикс — одна строка в двух местах
   (`.env.example`, `config.py`): поставить `claude-sonnet-4-6`.

### Замечания, не блокирующие

2. **Глобальный `exit_router` перехватывает «🛑 Завершить» и «🛑 Завершить
   сессию» раньше `do.router`.** Проверил: в `do.handle_conversation` ветка
   выхода делает только `state.clear()` — ничего не теряется, меняется лишь
   текст ответа («✅ Диалог завершён.» → «✅ Завершено. Возврат в главное
   меню.»). Регрессии нет, но текст стоит сохранить прежним.
3. **Фикс закрывает только 🛑-кнопки.** Остальные кнопки главного меню
   («✨ Запрос», «📅 Неделя», «⚙️ Настройки»), нажатые внутри урока или
   /do-диалога, по-прежнему уедут в Claude как промпт. Тот же класс бага,
   решён частично.
4. **`get_study_session` дублирует логику `_build_session`** (resolve пути,
   boot-assertion на persona). Просится общий хелпер.
5. **`enter_study` проверяет `settings.vault_path / "study" / "profile.md"` без
   `.resolve()`** — остальной рантайм пути резолвит. При запуске бота не из
   корня проекта приветствие покажет не тот вариант. Косметика.
6. **Тестов и CI в репозитории нет вообще** — раздел «Проверено» в описании PR
   проверяется только на слово. Автоматически подтвердить ничего нельзя.
7. **Репетитор работает с `--dangerously-skip-permissions` в каталоге vault.**
   Запрет «не писать в MEMORY.md» держится только на тексте persona, технически
   не ограничен. Для своей сессии это уже норма в этом проекте, но тут код
   внешнего контрибьютора.

## Гонка при холодном старте — проверил, всё в порядке

`enter_study` греет сессию в фоне, пока пользователь уже может прислать вопрос.
`ClaudeSession._locked()` по умолчанию блокирующий (`fcntl.flock` без
`LOCK_NB`), так что `ask` дождётся прогрева, а не упадёт с «could not acquire
pane lock».
