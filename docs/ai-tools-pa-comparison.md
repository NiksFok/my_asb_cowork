## TL;DR — Краткие выводы

| Инструмент | Сильнейшая сторона | Слабое место | Рекомендован для |
|---|---|---|---|
| **Nessy** (QwenCode) | Приватность, NESSY.md semantic layer, git worktrees, @-ссылки | Слабая модель (Qwen vs frontier), нет fleet/scheduling | Чувствительные данные, команды уже на нём |
| **Codex** (OpenAI) | Data science, финотчётность, open-source | Слабый semantic layer, нет scheduling | Аналитические пайплайны, code-first задачи |
| **Claude Code** (Anthropic) | Semantic layer, agent harness, автоматизация | Rate limits, proprietary | Системная автоматизация, fleet of agents |

**Главный вывод:** Ключевой факт, который меняет анализ: Nessy построен на Qwen Code, который сам является форком Claude Code. Это означает, что **архитектурно все три инструмента похожи** (агентский цикл, MCP, Unix-философия). Реальный дифференциатор — качество модели под капотом. Для стратегии ИИзации аналитиков (agent harness + semantic layer + fleet of agents) **Claude Code является наиболее зрелой платформой** за счёт frontier-модели и зрелого инфраструктурного стека (Routines, Agent SDK, CLAUDE.md иерархия). Codex — сильная альтернатива для code-first и data science задач с open-source прозрачностью. Nessy обоснован при жёстких требованиях к приватности данных, но модельный gap уже чувствуется на сложных аналитических задачах.

**Рекомендуемая комбинация:** Claude Code (основной инструмент) + Codex (data science / финансовая аналитика) + Nessy (локальный контур для чувствительных данных).

## 1. Контекст и постановка задачи

Команда продуктовых аналитиков (ПА) работает с тремя AI-инструментами:

- **Nessy** — внутренняя сборка на базе форка Qwen Code (Qwen Code — форк Claude Code); полноценный агентный CLI с MCP, веб-поиском и интеграциями, развёрнутый на инфраструктуре компании
- **Codex** — облачный CLI-агент OpenAI, запущен в апреле 2025, использует модели серии GPT-5.x
- **Claude Code** — CLI-агент Anthropic, GA с мая 2025; также доступен в VS Code, JetBrains, web

Задача: выбрать инструментальный стек, максимально отвечающий нуждам аналитиков, а именно:

1. **Доступ к данным** — интеграция с дашбордами, хранилищами, BI-системами
2. **Семантический слой** — единое место знаний о продукте и рынке, доступное агентам
3. **Agent harness** — автоматизация нон-кодовых задач: отчёты, мемо, root-cause, презентации
4. **Автоматизация сотрудников** — возможность создать fleet of agents для рутинных операций

Текущая гипотеза команды: Nessy на Qwen уже уступает frontier-моделям и нужна замена или дополнение.

## 2. Описание инструментов

### 2.1 Nessy — локальный CLI на базе QwenCode

**Что это.** Nessy — корпоративная сборка на базе форка QwenCode. Работает полностью on-premise: модели запускаются локально (Qwen 7B/14B через Ollama или аналог), без отправки данных во внешние API. Интерфейс — терминал (CLI).

**Архитектура.** Агентский цикл аналогичен другим CLI-агентам: запрос → инструменты (чтение файлов, выполнение кода) → ответ. MCP поддерживается, но с ограничениями — в длинных сессиях наблюдается _state confusion_: агент то видит MCP-инструменты, то "забывает" о них (задокументировано внутренне).

**Модели.** Qwen 7B–14B в зависимости от конфигурации железа. Qwen3-4B через LoRA fine-tuning может достигать точности 8B-модели в узком домене (паттерн из опыта CyberSecQwen), что даёт пространство для специализации. Однако по общим метрикам (reasoning, long context, instruction following) Qwen 7–14B существенно уступает frontier-моделям (GPT-5.5, Claude Opus 4.7).

**Контекстный механизм: `@`-ссылки и NESSY.md.** Nessy поддерживает `@`-синтаксис для быстрого включения контекста:

```bash
# Включить файл целиком
nessy "Объясни логику в @src/utils/auth.py"

# Включить содержимое директории (листинг файлов)
nessy "Какова структура @src/components?"

# Получить данные из MCP-ресурса
nessy "Покажи данные из @github:repos/owner/repo/issues"
```

При `@`-ссылке на файл Nessy автоматически подтягивает `NESSY.md` из директории этого файла и всех родительских директорий — это аналог path-scoped rules в CLAUDE.md. Инструкции и знания о проекте можно хранить в `NESSY.md` рядом с кодом, и они будут автоматически попадать в контекст при работе с соответствующими файлами. Это базовый, но рабочий механизм семантического слоя.

**Управление сессиями.** Nessy хранит историю разговоров локально и поддерживает возобновление:

```bash
# Продолжить последний разговор
nessy --continue

# Продолжить последний разговор с конкретным запросом (для скриптов/CI)
nessy --continue --p "Покажи прогресс"

# Интерактивный выбор сессии — список с метаданными:
# сводка, прошедшее время, кол-во сообщений, git-ветка
nessy --resume
```

**Параллельные сессии через Git worktrees.** Для работы над несколькими задачами одновременно поддерживается изоляция через git worktrees:

```bash
# Создать изолированное рабочее дерево с новой веткой
git worktree add ../project-feature-a -b feature-a

# Запустить отдельный экземпляр Nessy в этом дереве
cd ../project-feature-a && nessy
```

Каждое рабочее дерево имеет отдельную файловую систему, но использует общую историю git. Это позволяет запускать несколько агентных сессий параллельно без конфликтов — ближайший аналог background agents в Claude Code, реализованный на уровне git-инфраструктуры.

**Что работает хорошо:**
- Полная приватность: данные не покидают периметр
- Нет зависимости от интернета и внешних API
- Свободная кастомизация: fine-tuning, промпты, инструменты — всё под контролем
- Нет лимитов использования
- `NESSY.md` — базовый semantic layer, загружается автоматически по `@`-ссылке
- `--continue` / `--resume` — управление историей сессий, включая неинтерактивный режим для скриптов
- Git worktrees — параллельные изолированные сессии без конфликтов
- `@`-ссылки на файлы, директории и MCP-ресурсы в одном синтаксисе

**Что не работает:**
- Качество вывода значительно ниже frontier-моделей
- Нет готовых интеграций с внешними системами (Google Drive, Jira, Slack)
- Проблемы MCP в длинных сессиях → сброс контекста
- `NESSY.md` — плоская структура без org/team/project иерархии (в отличие от CLAUDE.md)
- Нет scheduling и automation pipeline
- Нет Agent SDK для программного управления флотом агентов
- Нет нативных sub-agents и background agents (worktrees — ручной обходной путь)

### 2.2 OpenAI Codex

**Что это.** Codex CLI — терминальный агент OpenAI, open-source (Apache-2.0), запущен в апреле 2025 и набравший 67 000+ звёзд на GitHub. Не путать с оригинальным Codex 2021 (модель дополнения кода). Написан преимущественно на Rust (96%), что обеспечивает высокую скорость.

**Архитектура.** Агентский цикл: пользовательский запрос → промпт + история → HTTP POST к Responses API → инструмент или финальный ответ → повтор. Вся история передаётся в каждом запросе (stateless), что обеспечивает Zero Data Retention (ZDR). Кэширование промптов: статичный контент (инструкции) — в начало, переменный — в конец, что снижает стоимость при повторных запросах.

**Модели.** Актуальный стек (май 2026):

| Модель | Назначение |
|---|---|
| `gpt-5.5` | Frontier: сложные задачи, computer use, ресёрч |
| `gpt-5.4` | Профессиональная модель, coding + reasoning |
| `gpt-5.4-mini` | Быстрая, для субагентов |
| `gpt-5.3-codex` | Специализирована на коде |
| `gpt-5.3-codex-spark` | Research preview, ~1000+ tokens/sec (Pro) |
| `codex-mini-latest` | API: $1.50/M input, $6/M output |

**Sandboxing.** Уникальное преимущество: kernel-level изоляция.
- macOS: native Seatbelt framework
- Linux: Landlock + seccomp
- Windows: выделенный пользователь `CodexSandboxOffline/Online` + Windows Firewall

**Кейсы из реального использования:**
- NVIDIA: 10x ускорение ML-рабочих процессов на GPT-5.5, автономная отладка, трансляция Python→Rust с 20x производительностью
- Финансовые команды: MBR-нарративы, проверка моделей, прогнозные сценарии, интеграция с Google Drive / SharePoint / Box / Office 365
- Бизнес-операции: агрегация контекста из трекеров, KPI-дашбордов, Slack → первый черновик статус-отчёта автоматически
- Data science: root-cause анализ и KPI-мемо без ручного сбора данных

**MCP и интеграции:**
- 200+ MCP серверов через Docker MCP Toolkit
- 20 000+ кросс-апп инструментов
- Поддержка STDIO и streaming HTTP MCP
- Проект-скоупированный конфиг (`.codex/config.toml`)
- Нативно: Google Drive, SharePoint, Neo4j, Postgres, браузерная автоматизация

**Управление и автоматизация:**
- Мобильное управление через ChatGPT (одобрение команд агента на ходу)
- Remote SSH (secure relay, без открытия портов)
- Programmatic access tokens для CI/CD
- Hooks для автоматизации post-action событий
- HIPAA-compliant для healthcare

**Ограничения:**
- Только терминал (нет IDE-плагина как первоклассного)
- Semantic layer только через AGENTS.md (статичный файл, 32 КБ лимит)
- Нет встроенного scheduling (нужно строить самостоятельно)
- MCP серверы не изолированы сандбоксом Codex — ответственность за безопасность на стороне MCP-сервера
- Непоследовательность в длинных сессиях

### 2.3 Claude Code (Anthropic)

**Что это.** Claude Code — CLI-агент Anthropic, вышел в general availability в мае 2025. Доступен в терминале, VS Code, JetBrains, desktop-приложении и браузере. Строится вокруг трёх концепций: CLAUDE.md (семантический слой), MCP (первоклассная интеграция), Agent SDK (программная оркестрация).

**Реальные метрики от Anthropic (CFO Кришна Рао, 2026):**
- Claude Code пишет **90%+ кода** внутри Anthropic
- Финансовое закрытие готово на **90–95%** до касания человека (30 мин вместо часов)
- Anthropic **нанимает больше** людей, не меньше — каждый становится менеджером флота агентов

**Архитектура памяти и семантического слоя.** Ключевое отличие от конкурентов:

```
/etc/claude-code/CLAUDE.md     ← управляемая IT-политика (org-wide)
~/.claude/CLAUDE.md            ← личные предпочтения (все проекты)
./CLAUDE.md                    ← командные правила (в git)
./CLAUDE.local.md              ← личные правила проекта (gitignored)
./.claude/rules/*.md           ← контекстные правила по путям файлов
```

Каждый файл загружается в сессию как контекст. Это **живой семантический слой**: правила и знания о продукте, домене, метриках — в одном месте, доступном каждому агенту автоматически.

Дополнительно — **auto memory**: Claude сам записывает наблюдения о проекте (`~/.claude/projects/<project>/memory/MEMORY.md`), и они загружаются в следующие сессии.

**Skills** — переиспользуемые агентные workflow, описанные в `.claude/skills/*/SKILL.md`. Вызываются слэш-командами. Например: `/analyze-kpi`, `/generate-report`, `/root-cause`.

**MCP как first-class mechanism.** Claude Code рассматривает MCP как основной механизм расширения:
- Google Drive, Jira, Slack, GitHub/GitLab, Postgres, SQLite, Playwright (браузер)
- Сотни community MCP серверов
- Claude API MCP Connector (public beta, февраль 2026)
- Desktop Extensions (.mcpb) — one-click установка

**Agent SDK (Python / TypeScript):**

```python
from claude_agent_sdk import query, ClaudeAgentOptions

async for message in query(
    prompt="Подготовь KPI-мемо по метрикам из /data/metrics.csv",
    options=ClaudeAgentOptions(
        allowed_tools=["Read", "Bash", "WebFetch"],
        mcp_servers=[{"name": "gdrive", "transport": "stdio"}]
    ),
):
    print(message)
```

Полный контроль над инструментами, хуками жизненного цикла, субагентами и memory.

**Автоматизация (scheduling):**
- Routines — scheduled tasks на инфраструктуре Anthropic (работают без компьютера пользователя)
- Desktop scheduled tasks — локальный запуск с доступом к файлам
- GitHub Actions / GitLab CI/CD — native интеграции
- Slack: `@Claude` → PR с исправлением бага
- `/loop` — внутрисессионная репетиция задачи

**Нон-кодовые применения внутри Anthropic:**
- Глубокий ресёрч через большие документальные корпуса
- Создание Excel/PowerPoint/Word через Python-скрипты
- Финансовые агенты (инвестиционная оценка)
- Саппорт-агенты
- Личные ассистенты (бронирование, календарь)

**Benchmarks:**

| Бенчмарк | Claude Code / Anthropic | Codex / OpenAI |
|---|---|---|
| SWE-bench Verified (agentic) | Claude Opus 4.5: **80.9%** | GPT-5.5: **82.6%** |
| Terminal-Bench 2.0 | **65.4%** | **77.3%** |
| Blind code quality (human eval) | **67%** побед | 25% побед |
| Последовательность | высокая | средняя |

**Ограничения:**
- Proprietary (нет open-source версии)
- Rate limiting — главная жалоба в сообществе
- Использование делится между chat и CLI (один пул токенов)
- Нет kernel-level sandboxing (application-layer hooks)
- Дороже в токенах на задачу, чем Codex (~4x)

## 4. Детальное сравнение

### 4.1 Доступ к данным

#### Nessy
Несмотря на on-premise модель, Nessy поддерживает MCP и web search. Задокументированные интеграции: **Sage, Wiki, GitLab, Jira** — через MCP-серверы читает проектные документы, задачи, тикеты. `@`-синтаксис позволяет ссылаться на файлы, директории и MCP-ресурсы единым образом. Pipe-режим закрывает базовый event-driven мониторинг (`tail -f app.log | nessy -p "Сообщи если DAU упал"`).

Ограничения: нет нативных коннекторов к офисным экосистемам (Google Drive, SharePoint). MCP state confusion в длинных сессиях. Настройка MCP — ручная работа.

**Вывод:** ★★★☆☆ — корпоративные системы (Jira, Wiki, Sage, GitLab) через MCP, но менее зрелый ecosystem

#### Codex
Нативные интеграции с офисными экосистемами: **Google Drive, SharePoint, Box, Office 365**. Через Docker MCP Toolkit — 200+ серверов, включая базы данных (Postgres, Neo4j), браузерную автоматизацию. Задокументированный паттерн: Codex собирает контекст из трекеров задач, KPI-дашбордов, Slack-переписок и генерирует первый черновик аналитического документа.

Дополнительно: встроенный web search (cached / live), возможность читать скриншоты дашбордов через image input.

**Вывод:** ★★★★☆ — сильные интеграции, особенно для офисных экосистем

#### Claude Code
MCP как основной механизм: те же категории подключений (Drive, Jira, Slack, GitHub, БД, браузер), плюс Claude API MCP Connector (public beta) — подключение MCP прямо через API без локальной инфраструктуры. Skills позволяют инкапсулировать логику доступа к данным в переиспользуемый workflow.

Monitor tool — реактивное чтение: агент подписывается на вывод фонового скрипта и реагирует на события (например, аномалия в метрике → уведомление). Pipe mode: `tail -200 metrics.log | claude -p "Сообщи если DAU упал > 10%"`.

**Вывод:** ★★★★★ — MCP first-class, reactive monitoring, Skills как data access layer

### 4.2 Семантический слой

Семантический слой = единое место, где хранятся знания о продукте, рынке, метриках, соглашениях — и эти знания автоматически становятся контекстом для каждой агентной сессии.

#### Nessy
`NESSY.md` — механизм, аналогичный CLAUDE.md: файл кладётся рядом с кодом (или в родительские директории), и при `@`-ссылке на файл агент автоматически подтягивает все `NESSY.md` по пути до корня. Это даёт базовый path-scoped semantic layer.

Пример структуры:
```
/project/NESSY.md               ← общие правила проекта
/project/analytics/NESSY.md     ← контекст аналитической директории
/project/analytics/metrics.py   ← при @ссылке оба NESSY.md загрузятся
```

Ограничения: нет org/user/project иерархии (только файловая система), нет auto memory (агент не пишет в NESSY.md сам), нет managed IT-policy, нет Skills как переиспользуемых workflow.

**Вывод:** ★★☆☆☆ — базовый path-scoped механизм есть, но без иерархии и живой памяти

#### Codex
`AGENTS.md` — единственный механизм. Статичный markdown-файл, 32 КБ лимит, загружается из git root до текущей директории. Поддерживается кросс-инструментами (Cursor, Windsurf), что удобно для кросс-тул workflow.

Ограничения: нет иерархии (org → team → project), нет path-scoped правил, нет auto memory (Claude сам не обновляет файл), нет managed policy для IT-управления.

**Вывод:** ★★☆☆☆ — базовый уровень, статичный

#### Claude Code
Наиболее развитая реализация среди трёх инструментов:

**Иерархия CLAUDE.md:**
```
Org-wide (IT): /etc/claude-code/CLAUDE.md
User (personal): ~/.claude/CLAUDE.md
Project (team): ./CLAUDE.md, ./.claude/CLAUDE.md
Local (personal+project): ./CLAUDE.local.md
Path-scoped: .claude/rules/metrics.md → загружается при открытии файлов metrics/*
```

**Auto memory:** Claude сам фиксирует наблюдения — "формула DAU включает только активацию через push", "дашборд N15 — источник правды по retention". Эти факты загружаются автоматически. Аналог knowledge accumulation без ручной редакции.

**Skills:** агентные workflow как переиспользуемый code: `/root-cause`, `/generate-weekly-report`, `/kpi-memo` — каждый skill описывает протокол, источники данных, формат вывода.

**Import-синтаксис:** `@path/to/metric-definitions.md` — подтягивание внешних документов прямо в контекст агента.

Это единственный инструмент, позволяющий построить **настоящий living semantic layer**: человек пишет базовые правила → агент автоматически обогащает → следующая сессия стартует с накопленным контекстом.

**Вывод:** ★★★★★ — самый развитый semantic layer из трёх

### 4.3 Agent harness

Agent harness = способность инструмента выполнять нон-кодовые задачи в автономном режиме: аналитические мемо, презентации, root-cause, обзоры данных.

#### Nessy
Полноценный агентный цикл: редактирует файлы, запускает команды, создаёт коммиты. MCP-контекст из Jira/Wiki/Sage позволяет агрегировать корпоративный контекст. `NESSY.md` с описанием метрик и бизнес-правил автоматически попадает в контекст при `@`-обращении к файлам домена. Pipe-режим и CI-интеграция (`nessy -p "..."`) дают базовый harness для автоматических задач.

Ключевое ограничение: качество reasoning Qwen 7–14B на сложных аналитических задачах (многоступенчатый root-cause, связный аргументированный нарратив) заметно ниже frontier моделей. Нет аналога Skills как декларативных workflow-пакетов.

**Вывод:** ★★★☆☆ — инфраструктура агента есть, качество вывода — главный сдерживающий фактор

#### Codex
Хорошо задокументированные аналитические кейсы:

- **Data science:** Codex берёт дашборды, определения метрик, бизнес-контекст → выдаёт готовый root-cause с диаграммами и оговорками. Аналитик смещается от сбора данных к валидации черновика.
- **Финансовая отчётность:** MBR-нарратив, проверка моделей, анализ вариаций, прогнозные сценарии — без написания кода. Google Drive / SharePoint как источники.
- **Бизнес-операции:** агрегация из трекеров, KPI-систем, Slack → первый черновик статус-отчёта с разделением фактов и интерпретации.

Image input: читает скриншоты дашбордов, что критично для аналитиков без прямого SQL-доступа к данным.

Image generation: иконки, баннеры, иллюстрации для презентаций через gpt-image-2.

**Вывод:** ★★★★☆ — сильный для аналитических артефактов, особенно финансовых и data science

#### Claude Code
Все те же аналитические сценарии + мощный агентный слой:

- **Sub-agents:** свинец-агент ставит задачу → несколько параллельных субагентов обрабатывают разные датасеты или разные разделы отчёта → финальный агент собирает результат.
- **Background agents:** несколько полноценных сессий параллельно, управляемых с одного экрана.
- **Skills:** `/analyze-kpi` может включать протокол: загрузить определения метрик из CLAUDE.md → запросить данные через MCP → сгенерировать мемо по шаблону → поставить задачу в Todoist на ревью. Всё в одном вызове.
- **Document generation:** Excel, PowerPoint, Word через Python (`openpyxl`, `python-docx`) прямо из данных.
- Внутри Anthropic используется для: глубокого ресёрча, нотинга знаний, финансовых агентов, саппорт-агентов.

**Вывод:** ★★★★★ — наиболее полная реализация agent harness с учётом нон-кодовых задач

### 4.4 Потенциал автоматизации сотрудников

Речь о способности инструмента стать платформой для fleet of agents — автономных агентов, берущих рутину аналитиков на себя с minimal human oversight.

#### Nessy
Встроенного scheduling и event-driven запуска нет. Однако есть два полезных механизма:

- **`--continue --p "..."` в неинтерактивном режиме** — позволяет запускать Nessy из cron или CI-скриптов: агент продолжает последний разговор с заданным промптом и завершается. Это примитивная, но рабочая автоматизация.
- **Git worktrees** — несколько экземпляров Nessy в разных ветках одновременно. Аналитик может запустить параллельно: один агент в `feature/kpi-report`, другой в `feature/cohort-analysis`, без конфликтов по файлам.

```bash
# Запустить агента по расписанию (через cron)
0 9 * * 1 nessy --continue --p "Собери KPI за неделю и положи в weekly-report.md"

# Параллельная работа в двух ветках
git worktree add ../analytics-cohort -b feature/cohort && \
  cd ../analytics-cohort && nessy &
```

Ограничения: нет Agent SDK, нет native Slack/GitHub интеграций, нет managed infrastructure — всё нужно собирать руками поверх shell-скриптов.

**Вывод:** ★★☆☆☆ — минимальная автоматизация через CLI-флаги и worktrees, fleet требует ручной оркестрации

#### Codex
- Programmatic access tokens для CI/CD интеграций
- Hooks: post-action события (например, после завершения задачи → уведомление)
- Remote SSH: агент работает на сервере, управление с мобильного
- Мобильное одобрение: async workflow — агент выполняет задачи в фоне, человек одобряет ключевые шаги через ChatGPT на iPhone
- 4M+ еженедельных пользователей, HIPAA-compliant
- Auto-review mode: reviewer-агент проверяет действия основного агента до выполнения

Нет: встроенного scheduling (нужно настраивать через cron/CI), нет event-driven триггеров из внешних систем (Slack mention → задача).

**Вывод:** ★★★☆☆ — хорошая база, нужны внешние компоненты для полноценного fleet

#### Claude Code
Наиболее зрелая инфраструктура для fleet:

- **Routines** — scheduled tasks на инфраструктуре Anthropic: не нужен работающий компьютер. Пример: каждый понедельник в 09:00 агент собирает метрики недели, формирует мемо, кладёт в Google Drive и создаёт задачу в Jira на ревью.
- **GitHub/GitLab CI/CD** — native: push → автоматический анализ, PR → review комментарии
- **Slack**: `@Claude исправь баг #1234` → агент создаёт PR
- **Agent SDK** — Python/TypeScript: программная оркестрация любого количества агентов с разными tool sets, промптами, memory. Основа для собственных аналитических пайплайнов.
- **Managed Agents** (REST API): Anthropic держит инфраструктуру, ваш код только отправляет задачи и получает результаты
- **Hooks** (17 типов): PreToolUse, PostToolUse, Stop, SessionStart — контроль каждого действия агента
- **Sub-agents с memory**: каждый субагент накапливает собственный контекст

Концепция CFO Anthropic "каждый сотрудник управляет флотом агентов" — реализуется именно через этот стек.

**Вывод:** ★★★★★ — наиболее зрелая платформа для fleet of agents

### 4.5 Безопасность и приватность

#### Nessy
- Полная приватность: данные не покидают инфраструктуру
- Нет зависимости от внешних API
- Возможен fine-tuning на корпоративных данных без их передачи
- Слабость: сама по себе инфраструктура требует обеспечения безопасности (patch management, доступ)

**Вывод для чувствительных данных:** ★★★★★ — лучший вариант при жёстком data sovereignty

#### Codex
- Kernel-level sandboxing (macOS: Seatbelt, Linux: Landlock+seccomp, Windows: dedicated user + Firewall)
- Сетевой доступ **отключён по умолчанию**, allowlist через конфиг
- Zero Data Retention (ZDR) через stateless HTTP запросы
- OpenTelemetry audit logging с захватом intent (не только что, но и зачем)
- HIPAA-compliant
- Трёхуровневая модель риска: технические границы → политики одобрения → audit

MCP серверы НЕ изолированы — ответственность за их безопасность лежит на разработчике MCP-сервера.

**Вывод:** ★★★★☆ — сильный для cloud-инструмента, kernel-level защита

#### Claude Code
- Application-level hooks (нет kernel-level, в отличие от Codex)
- Managed policy через `/etc/claude-code/CLAUDE.md` — IT-managed правила
- Поддержка Amazon Bedrock / Google Vertex AI — данные в вашем облаке, не у Anthropic
- Hooks PreToolUse / PostToolUse: возможность блокировать или логировать любое действие
- Нет kernel-level sandboxing: агент ограничен permission_mode (acceptEdits, read-only)

**Вывод:** ★★★☆☆ — достаточно для большинства корпоративных задач, слабее Codex по изоляции

### 4.7 Качество модели и вывода

#### Nessy (Qwen 7–14B)
- Значительно уступает frontier на сложных reasoning-задачах
- Хорошо справляется с простыми template-based задачами
- LoRA fine-tuning может улучшить точность в узком домене, но не устраняет gap на общих задачах

#### Codex (GPT-5.5 / gpt-5.3-codex)
- SWE-bench: 82.6% (frontier уровень)
- Terminal-Bench: 77.3% — лидер в терминальных задачах
- Blind eval: 25% побед по quality (vs Claude Code)
- Скорость: gpt-5.3-codex-spark — 1000+ tokens/sec
- Непоследовательность: один и тот же запрос может дать разные результаты

#### Claude Code (Claude Opus 4.x)
- SWE-bench: 80.9% с Claude Code harness (важно: сам harness добавляет ~18% к результату)
- Blind eval: 67% побед по качеству кода
- Высокая последовательность: почти идентичные результаты при повторных запросах
- Лучший в multi-file refactoring, frontend, сложных reasoning задачах

**Для аналитических задач (мемо, root-cause, нарратив):** Claude Code стабильно превосходит по качеству структуры, аргументации и следованию инструкциям.

### Дополнение: UX и управление сессиями

Для аналитиков, работающих с длинными контекстами и возвращающихся к задачам через несколько дней, механизм управления сессиями критичен.

| Возможность | Nessy | Codex | Claude Code |
|---|---|---|---|
| Возобновление последней сессии | `--continue` | `codex resume` | Project memory автоматически |
| Выбор конкретной сессии | `--resume` (UI: время, сообщения, ветка) | По session ID | По session ID через SDK |
| Неинтерактивный режим (CI/cron) | `--continue --p "..."` | `codex exec "..."` | `claude -p "..."` |
| Параллельные сессии | Git worktrees (вручную) | Subagents (нативно) | Background agents (нативно) |
| Что сохраняется между сессиями | Транскрипт разговора | Транскрипт + компакция | CLAUDE.md + auto memory (знания) |
| `@`-ссылки в запросе | Файлы, директории, MCP-ресурсы | Нет | Файлы через `@path/` |

Ключевое концептуальное различие: Nessy и Codex возобновляют **разговор** (что говорили). Claude Code возобновляет **контекст** (что узнали) — агент несёт накопленные знания о проекте в каждую новую сессию через auto memory.

## 6. Рекомендации по сценариям

### Сценарий 1: Семантический слой для команды аналитиков
**Задача:** создать единое место знаний — определения метрик, бизнес-контекст, соглашения по дашбордам — доступное каждому агенту автоматически.

**Рекомендация: Claude Code**
- CLAUDE.md иерархия: IT управляет org-wide правилами, тимлид — team-правилами, аналитик — personal
- Path-scoped rules: при работе с `metrics/*` агент автоматически получает определения метрик
- Auto memory: агент сам фиксирует новые паттерны по мере работы
- Import-синтаксис: подтягивание актуальных документов из wiki прямо в контекст

**Не подходит:** Nessy (нет механизма), Codex (только статичный AGENTS.md без иерархии)

---

### Сценарий 2: Автоматизация аналитических артефактов (root-cause, KPI-мемо)
**Задача:** аналитик вместо 2 часов сборки данных получает готовый черновик за 10 минут и тратит время только на валидацию.

**Рекомендация: Codex или Claude Code (зависит от источников данных)**

- Если данные в Google Drive / SharePoint / Office 365 → **Codex** (нативные интеграции, задокументированные кейсы для финтим)
- Если данные в корпоративных BI + нужен skills-driven протокол → **Claude Code** (Skills + MCP)

Паттерн Codex: входные данные (дашборд + метрики + Slack) → черновик с фактами и интерпретацией → аналитик валидирует

Паттерн Claude Code: Skills `root-cause` → CLAUDE.md с определениями метрик → MCP запрос к BI → мемо по шаблону → задача в Jira на ревью

---

### Сценарий 3: Fleet of agents — автоматизация рутины сотрудников
**Задача:** несколько агентов работают параллельно и асинхронно: еженедельные отчёты, мониторинг метрик, обработка Slack-запросов.

**Рекомендация: Claude Code**
- Agent SDK для программной оркестрации
- Routines: scheduled задачи на инфраструктуре Anthropic (не нужен работающий сервер)
- Slack native: `@Claude` → агент выполняет задачу → результат в треде
- Sub-agents с memory: параллельная обработка разных продуктовых областей
- Background agents: несколько сессий параллельно

**Nessy** — не может обеспечить fleet архитектуру без значительных кастомных доработок.
**Codex** — возможен через CI/CD + programmatic tokens, но нет native scheduling и Slack integration.

---

### Сценарий 4: Чувствительные данные (не могут покидать периметр)
**Задача:** работа с персональными данными, коммерческой тайной, финансовыми данными с жёсткими требованиями data sovereignty.

**Рекомендация: Nessy (primary) + Claude Code через Bedrock/Vertex (secondary)**
- Nessy: полная локальность, данные не покидают инфраструктуру
- Claude Code через Amazon Bedrock или Google Vertex AI: данные остаются в вашем облаке, не уходят к Anthropic
- Codex: ZDR снижает риск, но данные всё же обрабатываются на инфраструктуре OpenAI

---

### Сценарий 5: Code-first аналитика (data pipelines, ML)
**Задача:** написание и отладка аналитических скриптов, data pipelines, автоматизация обработки данных.

**Рекомендация: Codex**
- NVIDIA кейс: 10x ускорение ML-рабочих процессов
- Kernel-level sandbox: безопасный запуск кода
- Terminal-Bench: лидер в терминальных задачах
- Открытый исходный код: возможность аудита и кастомизации
- Subagents для параллельного выполнения независимых задач

**Claude Code** — альтернатива при необходимости superior code quality (67% vs 25% в blind eval).

- Подключить MCP для 1–2 ключевых источников данных (Jira, Google Drive или внутренний BI)
- Добавить Codex для специфических data science задач (где нужна работа с кодом и ML-пайплайны)
- Настроить path-scoped rules в CLAUDE.md под разные домены аналитики

### Этап 3 — Fleet automation (1–2 месяца)
- Использовать Agent SDK для первого автономного пайплайна (еженедельный KPI-отчёт)
- Настроить Routines для recurring задач
- Оценить Nessy: остаётся как инструмент для задач с чувствительными данными или постепенно замещается Claude Code через Bedrock

### Метрики успеха
- Время на подготовку первого черновика аналитического документа: снизить на 70%+
- Количество рутинных задач, автоматизированных агентами: +5 задач в месяц / аналитик
- Удовлетворённость команды качеством черновиков: NPS > 7
